# 意图说法扩充候选（2026-11-05）

用途：给 `app/agent/router.py` 的 `_RULES` 扩充关键词。本文档只是候选池，**不直接进代码**，需要人工筛选后再改 `_RULES`。

标注说明：
- 标准：和现有说法同义，可直接加
- 口语：更随意的日常说法
- 错字：常见同音/形近错误
- 缩写：简称或拼音首字母

边界提醒（三处高危）：
1. 「提醒」走提醒看板，「记录作业」走作业 DDL，两者不能混
2. 「修改木鱼：」前缀是写操作入口
3. 「食堂」两个字单独出现不能收进意图，会抢走 FAQ

# 边界风险清单（加词前必看）

## 1. remind vs homework（最高危）

规则顺序是 `CANCEL_REMIND → EDIT_REMIND → MY_REMINDERS → REMIND → HOMEWORK`，所以：

- 「提醒我明天交作业」→ 命中 REMIND（正确，`提醒` 在 HOMEWORK 前面）
- 「记录作业 周五交高数」→ 命中 HOMEWORK（正确，`记录作业` 是作业线专用词）
- **不要**给 HOMEWORK 加「提醒」相关词
- **不要**给 REMIND 加「记录作业」

## 2. 三条删除线的区分

| 说法 | 走哪条 | 结果 |
|---|---|---|
| 忘掉 X | memory_delete | 删长期记忆 |
| 删掉提醒 X | cancel_remind | 删提醒 |
| 删掉高数作业 | homework 的删除分支 | 删作业 |
| 删除这条记录 | **不要加** | 三边都能解释，会打架 |

## 3. canteen 不能收裸「食堂」

「食堂几点开门」是 FAQ，不能被 CANTEEN 抢走。只收「食堂有啥」「食堂推荐」「食堂菜单」这类**带查询动作**的组合。

## 4. news vs activities

- 「XX 活动 官方发布」→ NEWS（品牌/官方发布）
- 「有什么活动」→ ACTIVITIES
- 裸「推荐」不能给 ACTIVITY_ADVICE（会抢 CANTEEN 的「推荐吃啥」），现有规则已经把它去掉了

## 5. schedule 五条规则的顺序

`SCHEDULE_IMAGE → SCHEDULE_ALL → SCHEDULE_NEXT_WEEK → SCHEDULE_WEEK → SCHEDULE`

「这学期」「下周」「这周」这些词已经有专条，**不要**再加进最下面的 SCHEDULE，否则会被最宽的规则先吃掉。

## 6. usage 里的「周报」

现在「周报」归 USAGE（模型用量周报），不是学习周报。如果以后要做学习周报，得换词或提升规则优先级。

## 7. daily_report vs daily_report_set

- 「今日速览」「今天怎么样」→ DAILY_REPORT（看报告）
- 「早报改到七点」「早报只发课表」→ DAILY_REPORT_SET（改设置）
- 「早报」单独出现 → DAILY_REPORT_SET（现有顺序如此）

## 8. mail_send vs mail

`mail_send` 必须排在 `mail` 前面。像「邮件发一下」这种有歧义（可能是「把邮件发给我」），**不建议加**。

## 9. empty_room vs best_place

「自习」这个词在 EMPTY_ROOM 里，且 EMPTY_ROOM 优先级高于 BEST_PLACE。加「自习」类说法时要看有没有地点词：

- 「去哪自习」→ BEST_PLACE（有「去哪」）
- 「有自习的地方吗」→ 会命中 EMPTY_ROOM（因为含「自习」），这符合现有设计
